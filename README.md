## Запуск

Нужен Python 3.9 и свободное место для скачивания исходных данных и локальной выборки (желательно не менее 2 ГБ). На macOS можно открыть `run_local.command` двойным нажатием: он создаст окружение, установит зависимости и откроет ноутбук в JupyterLab.

Или из папки репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
jupyter lab experiments.ipynb
```

На Windows после создания окружения используйте `.venv\Scripts\activate` вместо `source .venv/bin/activate`.

В JupyterLab выполните **Run → Run All Cells**. Первый запуск скачает `multi_event.parquet`, `artist_item_mapping.parquet` и `album_item_mapping.parquet`; аудиоэмбеддинги не нужны. Данные и результаты подготовки по умолчанию хранятся в локальной папке `data/`. Чтобы использовать другое место, задайте переменную `YAMBDA_WORK_DIR` перед запуском JupyterLab. Файлы данных не входят в Git.

## Что воспроизводится

- Случайная группа 15% пользователей Yambda-50M, `seed=42`.
- Последние 150 дней событий, 3000 треков по числу разных положительных слушателей в train; фильтр не использует validation/test.
- Точные дубликаты удаляются; итог: **1 334 596 событий, 1479 пользователей, 3000 треков**.
- Релевантность для всех моделей: будущий `Listen+` (`played_ratio_pct > 50`) нового для пользователя трека из фиксированного каталога.
- Временное разбиение 70% / 15% / 15%, общие кандидаты и исключение известных треков. Основная метрика — NDCG@10, дополнительные — Recall@10 и Coverage@10.
- Модели: ItemKNN, iALS, EASE, FM с ID исполнителя и альбома, ALS с авторским градуированным таргетом. Их код находится в `models/`.

На test EASE получила NDCG@10 **0,1057** и Recall@10 **0,0503**. Полные таблицы, гиперпараметры и ограничения анализа приведены в ноутбуке.
